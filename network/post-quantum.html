RANNTA Post-Quantum Security Architecture

RANNTA operates active hybrid post-quantum security across two distinct Mainnet layers: protected authorization uses classical secp256k1/ECDSA plus ML-DSA-65, while validator-sensitive transport uses X25519 + ML-KEM-768 + HKDF-SHA256 + AES-256-GCM. Both are enforced with fail-closed HybridRequired policy semantics on their protected paths.

Post-quantum security should be a property of protected authorization and transport paths, not a label attached to one primitive.

1. Abstract

RANNTA implements a hybrid post-quantum authorization architecture for security-critical blockchain and digital-asset operations. On HybridRequired paths, the authorization model is explicitly dual-cryptographic: a classical secp256k1/ECDSA authorization factor and an ML-DSA-65 post-quantum authorization factor are both validated before the protected action is authorized.

ML-DSA-65 is standardized by NIST in FIPS 204. RANNTA integrates it as a required authorization factor rather than a decorative signature field. The native hybrid transaction structure carries both secp256k1 signature evidence and ML-DSA-65 signature evidence, and the policy gate rejects a legacy-only path when HybridRequired is active.

The architecture extends the same security thesis into validator and infrastructure authorization, key registration and rotation, canonical action binding, replay controls and external production integration through RANNTA PQ Cloud. On RANNTA X-Chain Mainnet, validator-sensitive transport is also active under HybridRequired using X25519 + ML-KEM-768 key establishment, HKDF-SHA256 key derivation and AES-256-GCM authenticated encryption.

RANNTA X-Chain Mainnet enforces hybrid post-quantum protection across validator-sensitive authorization and transport paths.

2. Active Dual-Cryptographic Security Model

Classical factor

secp256k1/ECDSA binds existing account and transaction authority to the protected operation.

Post-quantum factor

ML-DSA-65 provides an independent post-quantum authorization proof over the RANNTA canonical security context.

Mandatory hybrid authorization

RANNTA requires both classical secp256k1/ECDSA authorization and ML-DSA-65 authorization wherever HybridRequired is active; classical-only authorization is rejected.

On HybridRequired paths these factors are mandatory components of one authorization decision, not optional alternatives and not a migration-only mode.

3. Quantum Threat Model

RANNTA treats quantum migration as a system-wide authorization and protected-transport problem. Long-lived blockchain, treasury, custody and validator authority cannot be protected by changing only a wallet format while leaving policy, key lifecycle, replay controls, operational authorization and validator-sensitive transport unchanged.

Signature resilience

ML-DSA-65 adds a post-quantum authorization factor to security-critical paths.

Transport resilience

ML-KEM-768 is combined with X25519 for validator-sensitive HybridRequired transport sessions.

Migration continuity

The hybrid model strengthens cryptography without discarding established authorization and interoperability infrastructure.

5. Native X-Chain Hybrid Authorization

RANNTA X-Chain engineering exposes a native hybrid authorization surface for protected transfers and key lifecycle operations. The hybrid transfer model carries both a secp256k1_signature and an ml_dsa_65_signature. Key registration and rotation similarly bind classical account authority to ML-DSA-65 proof.

Hybrid transfer

Key registration and rotation

Legacy-path enforcement

When an account enters HybridRequired mode, legacy-only authorization is rejected on the protected path.

6. Validator and Consensus Authorization

RANNTA consensus engineering implements HybridRequired authorization surfaces across validator-sensitive proposal, vote and finality paths. Broader distributed validator deployment is the topology-scale expansion of this implemented authorization model.

The HybridRequired consensus authorization model is implemented independently of validator-count growth. Network expansion broadens distributed participation without redefining the protected authorization path.

7. Canonical Payload Binding and Replay Resistance

Cryptographic strength depends on context integrity. RANNTA binds authorization evidence to canonical fields such as chain identity, sender or subject, action, nonce, validity window, key version, policy version and operation identity. Consensus-sensitive paths additionally bind consensus context such as round or message type where applicable.

Executed transaction hashes and used operation identities are tracked so valid evidence cannot simply be reused to create a second authorized operation. The design goal is that a signature valid for one intent cannot silently become authority for another intent.

9. Crypto-Agility and Active Hybrid Transport

RANNTA does not freeze the protocol around a single primitive. ML-DSA-65 is the active post-quantum signature primitive for the current hybrid authorization architecture. The wider protocol remains crypto-agile as standards, operational requirements and production evidence evolve.

Transport is a separate security layer from authorization. RANNTA X-Chain Mainnet now enforces hybrid post-quantum protection on validator-sensitive transport paths using X25519 + ML-KEM-768 + HKDF-SHA256 + AES-256-GCM under HybridRequired policy. Production acceptance rejects plaintext-sensitive traffic, classical-only peer authentication, replayed records, modified ciphertext, modified AAD, wrong-session records and wrong-direction records, while fresh reconnects establish new sessions.

Scope boundary: the transport claim applies to validator-sensitive protected paths. It does not claim that every public RPC byte is ML-KEM protected.

10. Post-Quantum Scaling and Aggregation

Post-quantum signatures are larger than conventional elliptic-curve signatures, which makes batching, verification parallelism and proof aggregation important engineering domains. RANNTA's expansion program includes post-quantum authorization batching and aggregation so stronger cryptographic assurance can scale with network and infrastructure throughput.

The RANNTA design remains implementation-flexible: aggregation is treated as an optimization and proof-compression layer around authorization, not as a substitute for the underlying HybridRequired security policy.

RANNTA's security program advances from active hybrid authorization and validator-sensitive hybrid transport toward progressively broader post-quantum coverage across the full protocol stack.

  • Canonical PQ state integration: move post-quantum authorization state deeper into protocol-owned canonical state surfaces.
  • Validator-scale expansion: extend hybrid authorization evidence across broader distributed validator operation.

15. Conclusion

RANNTA's post-quantum architecture is built around a concrete security rule: protected authorization and validator-sensitive transport are hybrid, explicit and fail-closed. Classical secp256k1/ECDSA authority and ML-DSA-65 post-quantum authority are both active factors in the HybridRequired authorization path. X25519 and ML-KEM-768 are both active factors in the validator-sensitive protected transport handshake, with HKDF-SHA256 and AES-256-GCM protecting session records.

RANNTA then extends that model outward into key lifecycle, replay resistance, infrastructure integration and RANNTA PQ Cloud. The result is a security architecture designed to operate as production infrastructure while preserving clear scope boundaries between authorization, transport and public RPC compatibility.

RANNTA is building post-quantum resilience as operating infrastructure, not as a label.
